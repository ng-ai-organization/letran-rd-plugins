# Pilot acceptance test

Use a multi-product test such as:
- Collection: Test01
- Products: Dining table, dining chair
- Style: Modern European, youthful, simple
- Materials: powder-coated steel frame + woven synthetic rattan
- Indoor/Outdoor: Indoor
- Market: Europe
- Target price: blank
- Weaving image: optional one attached image

## Acceptance behavior

1. Automatically enter Collection Mode.
2. Produce a compact shared Design DNA.
3. Produce three genuinely distinct concept directions.
4. Use the weaving image as visual reference only, or self-propose a pattern if absent.
5. Generate a professional landscape concept board, not only one isolated render.
6. Generate a separate Indoor lifestyle image showing table and chairs together as one coherent collection. For Outdoor, use an appropriate outdoor context.
7. Let the user list review issues one by one without regenerating until review is complete.
8. After `xong review`, surface the next action to continue to technical definition; do not require the user to remember a command.
9. Stage 04 should fill technical data first, consult the company material reference only after concept selection, and ask at most 3-5 meaningful blockers.
10. Stage 05 should create BOM only, not costing; use controlled technical data and keep unsupported precision TBD.
11. Stage 06 should separate proposed packing dimensions from verified data and label derived loading accordingly.
12. Stage 07 should report file readiness honestly and create only files actually supported by the current tool environment.
13. At every stage transition, prefer clickable/suggested actions when supported; otherwise show short numbered choices.
14. Keep the same chat for revisions of Test01; recommend a new chat for a different project such as Test02.
